# FutureForms

Сервис форм отклика для карьерной платформы: менеджеры конструируют и публикуют анкеты по ссылке, студенты заполняют их без регистрации.

## Возможности

- **Админка менеджера** (`/admin`): список форм, создание, редактирование (текст, длинный текст, радиокнопки, чекбоксы; варианты, обязательность, порядок вопросов), публикация/снятие с публикации, удаление.
- **Публичная форма** (`/f/<slug>`): заполнение по ссылке, валидация обязательных вопросов и вариантов, автоматически сохраняемый черновик — можно вернуться и дописать позже, повторная отправка определяется по черновику.
- **Просмотр ответов**: список отправленных откликов и незаконченных, сводка по вариантам, конверсия в отправку, активность за 14 дней, выгрузка CSV.
- Слаги из названия формы с транслитерацией кириллицы (`стажировка → stazhirovka`).

## Запуск

1. Клонировать репозиторий

```bash
git clone https://github.com/gr33b0k/ft-test.git
```

2. Установить зависимости

```bash
npm install
```

3. Запустить

```bash
npm start
```

`npm start` поднимает оба сервиса (`concurrently`, без прод-сборки):

- клиент: `http://localhost:3000`,
- API-сервер: `http://localhost:4000`.

Порты настраиваются через корневой `.env` (образец — `.env.example`):

```
PORT=3000
SERVER_PORT=4000
```

Клиент проксирует запросы `/api` на сервер, поэтому запущенного клиента достаточно для работы.

## Сценарии для проверки

1. Откройте админку `http://localhost:3000/admin`, создайте форму, добавьте вопросы, опубликуйте.
2. Скопируйте ссылку кнопкой «Копировать ссылку» и откройте её — форма студента.
3. Начните заполнять, оставьте страницу; менеджер увидит «незаконченный отклик» на странице ответов.
4. Вернитесь по ссылке — ответы восстановятся; отправьте отклик.
5. На странице ответов: конверсия, сводка по вариантам, экспорт CSV.

## API

Админ (`/api/forms`):

- `GET /api/forms` — список форм;
- `POST /api/forms` — создание;
- `GET | PUT | DELETE /api/forms/:id`;
- `POST /api/forms/:id/publish` и `POST /api/forms/:id/unpublish`;
- `GET /api/forms/:id/attempts` — ответы формы.

Публичные (`/api/public/forms/:slug`, только для опубликованных):

- `GET /api/public/forms/:slug` — форма;
- `POST .../attempts/start` — начало заполнения (черновик);
- `PUT .../attempts/:attemptId` — сохранение черновика;
- `GET | POST` `.../attempts[/:attemptId]` — восстановление прогресса и отправка отклика (POST принимает опциональный `attemptId` для завершения черновика).

Ошибки отдаются JSON-ом: `{ error, details? }`.

## Хранение данных

JSON-файлы в каталоге `data/` (`data/db.json`, добавлен в `.gitignore`). Битый `db.json` автоматически сохраняется как `db.json.corrupted-<ts>`, база считается пустой.

## Стек

- **server/** — Express 5, TypeScript (ESM, запуск через `tsx`), без внешней БД.
- **client/** — React 19, Vite, Tailwind CSS 4, react-router-dom 7, lucide-react.
- **Тесты** — vitest 5 (115 тестов: интеграционные API-тесты сервера с временной БД, unit-тесты клиентской логики).

## Структура

```
server/          API (express): app.ts, routes.ts, validation.ts, db.ts, models.ts, tests/
client/
  src/
    app/         роуты (react-router)
    pages/       admin, form-editor, public-form, responses, not-found
    widgets/     forms-list, form-editor, public-form, responses-viewer, header
    entities/    модели форм и API-клиенты
    features/    submission (отправка/черновики)
    shared/      ui-компоненты, http-обёртка, утилиты
data/            JSON-хранилище (в .gitignore)
```

## Команды разработки

```bash
npm start                 # оба сервиса
npm run dev:server        # только сервер (:4000)
npm run dev:client        # только клиент (:3000)
npm run test              # все тесты (client + server)
npm run lint              # eslint клиента
npm run build:client      # прод-сборка клиента (tsc -b && vite build)
npm run typecheck         # ts --noEmit сервера
```
